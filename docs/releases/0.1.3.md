# Toad 0.1.3

This release simplifies application-defined native modules through CMeta Plugin
declarations and changes the script filename extension to `.toad`.

## Native modules

- Native module publication uses `CMETA_PLUGIN_DECLARE`. The existing
  `TOAD_PLUGIN_MODULE*` adapters keep their interface layout and import behavior.
- `TOAD_PLUGIN_FUNCTION` and `TOAD_PLUGIN_FUNCTION0` generate scalar function
  metadata and exact invocation through CMeta. The exported header-only
  `Toad::PluginABI` CMake target supplies producer headers without linking the
  Engine or Script runtime.
- `toad_script_context_register_plugin()` explicitly attaches all Function
  exports from a STARTED passive plugin to a Host context. Admission validates
  signatures, names and capacity atomically. The caller owns the address-stable
  CMeta registry; Toad holds its lease through final context cleanup, including
  retained module, instance and result objects.
- The scalar boundary supports bool/int/long/float/double IN parameters and
  scalar/void results. Exact value tags survive the Engine/MIR boundary. Invalid
  conversion and non-finite results fail with HOST_ERROR under the existing
  instance lifecycle. Native code remains trusted; registration does not prove
  purity or provide process isolation.
- A complete C11/C++17 two-module example exercises interpreter and JIT execution.
  Formal regressions cover typed calls, nested helpers, atomic rejection,
  owner/state checks and lease retention.

## Script extension migration

**Migration required:** rename `.tbs` script files to `.toad` and update their
`import()` / `import_module()` paths and CLI/script tooling references together.
Script import paths now require the case-sensitive `.toad` suffix. There is no
legacy suffix alias. Native imports such as `import("fin")` are unchanged.

All 21 repository scripts, current documentation and formal test paths use the
new extension. Regressions reject old or lookalike suffixes without executing
their contents.

## Dependencies and qualification

Dependency selections remain Base 0.1.8, CMeta 0.1.7, Utils 0.1.4, CNet 0.1.12,
CHttp 0.1.0 and vcpkg-cache 0.1.3. The release workflow qualifies the complete
native build/test/install graphs for Windows LLVM-MinGW x64, Linux Clang x64
and macOS Clang arm64, plus Android arm64 cross-build/install and ELF alignment.
Android qualification does not imply execution on a device. Original SDK
manifests and SHA256SUMS accompany the archives and Toad.Native package.
